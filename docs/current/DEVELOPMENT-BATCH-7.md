# Current registry privacy and honest creation recovery

Seventh bounded batch in the four-hour continuation, based on published sixth commit `e813af2f43f6d7c707f084c4472e5a6da8e50125`. Students and guardians use fresh session/list/session reads with abort and generation guards. Every new reload clears earlier principal/list state, and obsolete replies cannot populate a newer account view. Current authorization errors hide private data; temporary failures show a reload action without claiming an empty registry.

Student search filters names and admission numbers in the loaded authorized list. It shows exact loaded/matching/displayed counts and up to200 matches. It does not add server-side pagination or a whole-database search promise. The horizontally scrolling guardian table is a labelled keyboard-focusable region. Student View now uses native full-page navigation after a real browser probe reproduced the previous client-transition failure. Existing profile APIs, admission uniqueness and role/school authorization are unchanged.

Creation uses a synchronous in-page lock and verifies the current account before posting. Only a correlated201 acknowledges a saved profile. A subsequent list failure retains the saved fact separately. Every unknown create outcome clears displayed registry/principal state and freezes another create: these existing APIs have no UUID replay contract. The original administrator must reload an authorized list, compare submitted details, explicitly acknowledge possible duplication and start a blank new draft. No automatic retry or duplicate merge is added. Pending details remain private in memory and are hidden from another account, including another administrator. Navigation or hard reload loses the in-page reminder; multi-tab/cross-device duplicate prevention remains open.
