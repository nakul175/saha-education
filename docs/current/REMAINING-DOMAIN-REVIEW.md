1. **P1 — original writes retain stale authority.** A disabled administrator still creates a class (`201`), a demoted administrator creates a course (`201`), and a disabled administrator updates a school (`200`). A report draft still inserts after its student moves outside the administrator's school (`201`). A reassigned teacher still inserts a notice to a former-class guardian (`201`), and a disabled guardian still marks a notice read (`200`). Persisted rows/fields were inspected in each case. [Classes](../../lib/education/classes.ts), [courses](../../lib/education/courses.ts), [schools](../../lib/education/schools.ts), [report creation](../../lib/education/report-cards.ts) and [notifications](../../lib/education/notifications.ts) use prevalidation followed by mutations without a current actor/reference predicate. Next batch: guard the actual INSERT/UPDATE with matching enabled mapped actor, current role/school, record ownership and required current references; return a safe conflict/denial when the guard yields no row.

2. **P1 — class references can become invalid between checks and persistence.** Moving the selected course to another school immediately before class INSERT still returns `201`; the new class belongs to school A while its course belongs to school B. Disabling the selected teacher immediately before class UPDATE still returns `200` and persists the requested edit. [createClass/updateClass](../../lib/education/classes.ts) check the course and teacher only in earlier queries. These outcomes violate the existing same-school/enabled-teacher checks, independently of any future transfer policy. Next batch: include current course school and teacher role/school/enabled eligibility in both mutation statements; preserve existing class/history rows on rejection.

3. **P1 — a zero-row publication still creates a notice.** Moving the student outside the school after recipient assembly makes the conditional report UPDATE change zero rows. `published_at` stays null and the route returns `404`, yet one “Report Card Published” notice commits. In [publishReportCard](../../lib/education/report-cards.ts), the notices are unconditional INSERT values inside the same batch. Transactionality does not make their existence conditional on a successful publication. Next batch: couple notices to the actual authorized publication winner; prove that zero-row, revoked and losing concurrent publications create no new notice. Preserve established publication evidence and deterministic notice identities on legitimate retries.

4. **P1 — publication uses a guardian mapping removed before commit.** The reproducer invokes the actual reviewed profile-unlink service after recipient selection and before the publication batch. Publication returns `200`, but a new notice goes to the former guardian login. A fresh former-guardian session gets learner `404` while reading this newly misdirected notice, which includes the student's name. [Recipient assembly and notice insertion](../../lib/education/report-cards.ts) are separated by the race. Next batch: derive/recheck the explicit guardian-profile relationship, student/guardian/user school, guardian role and enabled mapped account within the notice INSERT. This changes eligibility for new notices; it does not authorize deleting historical notices or changing family-retention policy.

5. **P1 — downstream reads use the cached role/school.** Demoting the authenticated administrator before the report SELECT still returns an unpublished staff report (`200`, `publishedAt: null`). Late school changes still return the old school/course feed; disabling a teacher still returns classes; demoting the administrator still returns seven account IDs/names/roles from [the direct users query](../../app/api/users/route.ts); disabling a guardian still returns notices. [studentScope/classScope/guardianScope](../../lib/education/access.ts) constrain current records and links but do not themselves require a live matching actor. The new student and guardian profile reads correctly return empty lists under the same disablement interleaving, so the finding does not claim those guarded callers are exposed. Next batch: introduce a shared live actor predicate, apply it to remaining actual SELECTs and protect assembled responses/retries after dependent lookups. Keep family draft/result restrictions and existing school, class and relationship rules.
