## Scope and current reads

The existing [school page](../../app/schools/page.tsx) and [course catalog](../../app/courses/page.tsx) use unchanged school/course routes and services. All four roles retain existing current-school reads; only current administrator edits the existing school or creates a course. No create-school/bootstrap, course detail, teacher/class editor, tenant override, schema, API, UUID receipt, CAS or educational-policy change is added. Course codes remain globally unique across schools. Server SQL decides current access independently of presentation.

School reload hides the former account, saved details and input fields, then requires exact HTTP 200 session → exactly one complete matching school → exact HTTP 200 same ID/role/school session. Missing/duplicated/incomplete/foreign rows and unverified replies make the whole view unavailable. The current saved school card uses “No address supplied.” for both null and empty address; this display does not merge their SQL semantics.

Course reload similarly hides former account/catalog/form and reads session → whole catalog → administrator-only school list → same actor session. It checks complete course IDs/fields, duplicate IDs and current school; nullable descriptions stay compatible. Successful zero rows has an explicit authorized catalog count/empty state. Failed/malformed/denied data is unavailable rather than a successful empty or partial catalog. Required-principal [AppShell](../../components/app-shell.tsx) receives null at unverified boundaries and hides account header/role navigation without a cached fallback.

Abort, mounted generation and current-scope guards reject obsolete delivered reads. School captured controls require the exact current view object; course input/submit additionally pins draft revision. Current access checks surround reads/preflights; neither client continuously watches another tab's account or replaces SQL-time authority. An unmounted preflight starts no later save. A request already sent may still commit after leaving; client lifecycle checks cannot roll it back.

## School deliberate intent and ordinary acknowledgement

Same actor/school reload retains fields deliberately edited in that view and refreshes untouched fields from saved school. Before PATCH a fresh session/school/session snapshot again verifies the original administrator and target. Dirty name/address input overrides only its deliberately edited field; untouched values come from that fresh snapshot. This prevents a name-only draft from replacing a newly supplied address with the blank presentation of an earlier null.

Untouched address null omits address from the accepted PATCH body; deliberate clearing sends `address:""`. Omission means leave saved address unchanged, not set null. No existing endpoint can restore null from a non-null value. There is no CAS: a later administrator's changes can still be overwritten and the UI warns to review current saved details. A synchronous lock prevents duplicate same-frame saves. Only the existing accepted name/optional-address body and verified encoded school endpoint are submitted.

A known school update requires exact HTTP 200, a complete school result with original target/name and the submitted address when present. `createdAt` must equal the raw fresh preflight value; `updatedAt` must satisfy [exact stored timestamp validation](../../lib/education/stored-timestamp.ts). Raw legacy GET timestamps remain accepted and unchanged. Address omission allows acknowledgement of an independently changed current address; it does not assert an immutable full original snapshot.

The original submitted intent is a private ordinary acknowledgement, separate from subsequent current saved details. A failed follow-up read retains a generic known-save fact while hiding private original details/form. A fresh original administrator/current-school load permits the original submitted-name/address section. Another actor does not inherit that private acknowledgement. Neither known response nor current equality creates an immutable SQL receipt or durable recovery record.

Delivered 400/401/403/404/409 is classified as rejection: pending is cleared, unverified fields/header hide, and a fresh same original actor/school reload permits deliberately dirty input correction. Actual 400 validation and 403 role denial demonstrate no persistence in the related suite. Other named status projections are callback branch evidence only; projecting a status after a real commit does not establish rollback. No rejected path automatically sends another PATCH.

## School uncertain original comparison

Other sent failures, lost replies, invalid HTTP 200/HTTP 201 or malformed/mismatched acknowledgement retain original actor ID/role/school, target/endpoint, serialized body and submitted intent privately in mounted-page memory. The uncertain reminder hides prior private details, offers no resend and blocks new writes. Original submitted fields are visible only after a fresh matching current original administrator/school load. Different actors can receive their normal current school view but cannot view or clear the original reminder.

“I compared the saved details” performs another session/school/session read. It requires the same original administrator/target and exactly the same full saved-school key ID/name/address/createdAt/updatedAt as the just-reviewed view. If that key changes or the read fails, pending stays retained and another current review is needed. Stable completion sends zero PATCH, discards uncertainty and resets the edit form to current saved details. It explicitly does not confirm whether the earlier request saved and cannot restore an older concurrent change.

## Course creation and ordinary acknowledgement

The administrator form has native Course code, Course title, Description (optional) and Grade level labels. The target school comes from verified session/current school list. Same-frame locking, mounted generation/draft revision/current-scope and a fresh exact original administrator preflight precede the one non-idempotent POST. There is no client creation UUID, safe replay endpoint or typed school override.

Known creation requires exact HTTP 201 and original school/code/title/grade/description. Its createdAt must have exact canonical UTC millisecond shape `YYYY-MM-DDTHH:mm:ss.SSSZ`, a real calendar day and unchanged `toISOString()` round trip; updatedAt must equal that creation timestamp. Impossible February 30/non-leap February 29, hour 24, numeric/date-only values, offsets, omitted milliseconds and whitespace do not establish a known acknowledgement. Existing catalog timestamp strings remain accepted raw; presentation validation does not repair legacy records or change server storage.

A known response is recorded separately from fresh current catalog. Failed current reads preserve a generic known-save fact and block further creation while old catalog/form/private original reference hide. Fresh original administrator load may display the original returned reference/fields alongside current mutable catalog. A different actor receives only their normal scoped catalog and generic saved fact. This ordinary API acknowledgement is not an immutable actor receipt.

Delivered 400/409 clears pending comparison, hides unverified view and retains private original-account input for fresh correction. Actual 400 validation demonstrates no creation; the named 409 delivery test projects a real 201 after persistence and covers the branch, not a backend conflict/noninsert/rollback guarantee. Existing globally unique code collision still returns generic SQL 500 and follows uncertain comparison; it neither exposes a foreign-school row nor identifies a precise hidden collision cause.

## Course uncertain original comparison

Sent 403/5xx/network/empty/malformed/wrong-status/mismatched acknowledgement retains original actor/endpoint/exact serialized body/fields privately, clears current presentation and blocks another form. There is no retry or automatic POST. Fresh original administrator read displays original code/title/grade/description separately from actual current catalog. Matching fields cannot prove which request created a record; absent scoped rows cannot prove no commit or authorize blind repetition. Later legitimate saved edits stay current.

The native checkbox says “I checked the saved list against the original details and will start a new draft deliberately.” Checked “Finish comparison and start a new draft” sends zero requests, discards in-page uncertainty and starts blank. Reload resets comparison; current generation/original scope/pending-object checks reject stale checkbox/finish closures. Different administrators or family accounts cannot inspect/approve original details or bypass the pending action into another form. Original same-account unsent course input can be restored by a fresh reload; it is not transferred to another actor.
